# Repository Guidelines

This guide records repository-specific practices and agent workflow.

All BusBuddy source code, tests, documentation, progress files, and generated project artifacts must be stored under `/home/pavan/BusBuddy`. External folders may be read as reference inputs only; temporary extraction directories are not deliverable locations.

## Project Structure
Flutter/Dart accessible public-transport assistant prototype (Vellore, India demo): journey modeling, route search, accessible UI, realtime bus tracking, and Gemini Live voice. Source under `lib/` is feature-based (`features/`, `core/`, `data/`, `domain/`); tests mirror `lib/` under `test/`. `create_research_doc.py` generates the Word research document with `python-docx`. Docs: `docs/adr/`, `docs/superpowers/` (plans & specs), `docs/ui/`, `docs/audit/`. History: `progress.md` (compact log) + `docs/archive/progress-sessions-full.md` (verbatim full archive).

## Testing Guidelines
- Flutter widget tests with `WidgetTester`, `SemanticsHandle`, `pumpAndSettle`, and `pump` for timers. Test files live under `test/`, mirroring `lib/features/` and `lib/data/`.
- Voice-recognition lifecycles are driven through `AudioSpeechEngine.testStartListeningOverride` (with `testInputDeviceSummaryOverride` for device names) — the default test host never fires `onStarted`, which once hid a real web-mic bug (2026-10-18).
- Tap-target, label, contrast, and semantics guidelines from the research document apply.
- Manual Android testing with TalkBack and Accessibility Scanner recommended. Task testing needs at least one relevant blind/low-vision participant — blindfolded sighted participants alone are not sufficient. Usability measures: completion rate, time, errors, recovery actions, confidence, SUS.
- **Android voice is not verifiable headlessly.** Headless coverage: `test/features/ai_assistant/android_voice_turn_test.dart` drives the spoken-turn state machine through injected streams; `native_audio_channel_test.dart` asserts the bridge degrades honestly when platform channels are absent. An API 34 AVD run (2026-09-30) proved the build, install, permission contract, and honest-failure paths only — no working TTS engine, no hardware AEC, no TalkBack, and without a valid key `_awaitLiveReady` never opens the microphone. The permission dialog and the audio-in round trip need a physical device with a valid key (`flutter run -d android`, `adb logcat -s BusBuddyVoiceChannel:V`). Do not claim them verified from a green test run — or from an emulator run either. See ADR-004 §3.1 for exactly what is and is not proven.

## Key Runtime Notes

**Microphone honesty (BUS-P1-08) — state must be earned, never assumed:**
- `GeminiLiveScreen._isListening` starts `false` and flips only once capture is genuinely open. Every mic start — every platform — goes through `_gatedMicrophoneStart` → `_awaitLiveReady` (4 s). With no API key (the common first-run case) the screen says the microphone stayed off and names the key instead of promising "Listening…". Never default the flag to `true` (that also made the start early-return on its own guard) and never let a failure message say "still connecting" when no key is set — name the real reason.
- Web bridge (`__bb_start_recognition`, v10+): the fifth callback `onStarted` fires from recognition `onstart` — Chrome's permission prompt sits between `start()` and `onstart` — and only that flips the flag and plays the chime; until then the screen shows "Preparing the microphone…". When the session reaches "Live Ready" the continuous mic auto-opens. `__bb_input_devices` (v12) names the browser's audio inputs (labels once mic permission is granted; refreshed at install/start/error) so failures can say what Chrome actually sees.
- Every recognition cycle ends with capture closed, so `onEnd` must drop `_isListening` before `_scheduleRestartListening` — the restart guard is `!_isListening`. Leaving the flag true after a silent cycle killed the web mic while the screen still claimed "Listening…", and made the 3-cycle stop unreachable (2026-10-18).
- Three recognition cycles with no transcript at all (wrong input device, muted mic) stop the continuous loop with "I couldn't hear anything… (Chrome sees: …)" instead of restarting "Listening…" forever; `no-speech` is deliberately not an error. A **named** failure (`audio-capture`, `network`, `service-not-allowed`) is not silence: it stops the loop, shows Chrome's own reason plus the device list, and asks for an orb tap — never a silent restart into the same failure; the `onEnd` that follows must not overwrite its message.
- Regressions are pinned in `test/features/ai_assistant/voice_session_lifecycle_test.dart` (*BUS-P1-08 Microphone State Honesty*) and `ai_control_glow_test.dart`.

**Gemini Live key & connection:**
- Requires a valid Google AI Studio key, set via the in-app dialog or `--dart-define=GEMINI_API_KEY`. The key is **never written to disk** (pinned in `test/data/persistence_test.dart`: hydrate ignores it, snapshots exclude it) — an app restart needs re-entry unless it came from `--dart-define`.
- Every connect is gated on `GeminiLiveSession.validateApiKey` (`GET v1beta/models`). Statuses name the real failure: `Key Needed` / `Validating API key…` / `Key Invalid` / `Disconnected (code …)`; socket-open reports "Completing handshake…" — `Live Ready` only after `setupComplete`. A debounced (400 ms) settings listener reconnects on any key/model/voice change, so a key saved from the settings page reaches an open Live screen.
- Current model: `models/gemini-3.8-live`. Voices: `Aoede` (default), `Kore`, `Charon`, `Puck`, `Fenrir` — via Voice Assistant Settings or `--dart-define=GEMINI_VOICE`.
- The assistant executes tool calls in the background and answers in concise natural transit language — never reads raw JSON, function signatures, or execution mechanics aloud.

**Single-speaker audio — do not add a second voice path:**
- Gemini Live replies use only Gemini's streamed audio. `AudioSpeechEngine` stays muted for the whole `GeminiLiveScreen`; text-only replies remain visible in the transcript and never fall back to app TTS. This prevents late model audio from overlapping an offline TTS response. Barge-in (`onInterrupted`) must stop playback, not just TTS.
- Android PCM chunks are serialized through `ModelVoicePlayer`; do not let streamed chunks race the initial `startPlayback` call. Gemini `turnComplete` sends `finishPlayback`, and native `onPlaybackDrained` fires only after that marker, an empty queue, and the `AudioTrack` playback head catches up. Temporary gaps between model packets must never resume the microphone. Web keeps its Web Audio queue-drain timer. Text-only turns do not wait for a drain. A 30 s `_armWatchdog()` backstop covers a lost audio drain.
- Model audio is supported on Android and web (`ModelVoicePlayer.isSupported` = `kIsWeb || platformHasNativeAudio`). Platform detection uses `Platform.isAndroid` via `native_platform_io.dart`, **never `defaultTargetPlatform`** (flutter_test fakes it as Android). If model PCM is unavailable or cannot be scheduled, Live replies stay text-only. Web plays the same 24 kHz PCM16 through the existing Web Audio context (`__bb_play_model_audio` / `__bb_stop_model_audio`, bridge v6+).
- The page JS bridge is **verified, never assumed** (ADR-004 §3.5): `web_speech_real.dart` installs functions by evaluating JS into the page; calls resolve the entry point and invoke the **function reference** so a missing bridge is an observable `null`, not a `NoSuchMethodError`; every install verifies required entry points and resets the initialized flag if any is missing. Never "simplify" back to blind `js.context.callMethod('__bb_…')` calls.
- Forbidden: two producers in one turn, or a second `AudioTrack`/`TtsFallbackArbiter`-style owner (Chunk 43 deleted the arbiter — never resurrect it).
- **Single voice surface:** full-screen `GeminiLiveScreen` is the app's sole voice/chat assistant surface and sole audio-session owner; all "Ask BusBuddy" entry points push it directly. The floating bubble/multitasking window was removed (Chunk 42) — do not reintroduce a second audio/TTS owner without redesigning the single-speaker contract.

**Android voice I/O (ADR-004):**
- Audio I/O is platform-native. Android: `BusBuddyVoiceChannel` (`android/app/src/main/kotlin/com/busbuddy/app/BusBuddyVoiceChannel.kt`) — `TextToSpeech` replies, 24 kHz `AudioTrack` playback on `USAGE_ASSISTANCE_ACCESSIBILITY` (keeps hardware echo cancellation engaged while the mic is open), `ToneGenerator` chimes, 16 kHz mono `AudioRecord` capture streamed over the `busbuddy/voice/mic` event channel. `RECORD_AUDIO` is requested just in time (announced first, rationale-aware, "never ask again" detected via SharedPreferences). Chrome web uses the Web Speech APIs.
- Spoken questions reach Gemini Live: `GeminiLiveSession.sendRealtimeAudio` packs microphone PCM into `realtimeInput.mediaChunks` (`audio/pcm; rate=16000`), gated on `isReady` (socket open **and** `setupComplete`). One spoken turn is owned by `AndroidVoiceTurn` (`lib/features/ai_assistant/android_voice_turn.dart`): it forwards chunks, pauses while the assistant speaks, and reports every failure exactly once through `onTurnLost(reason, microphoneUnavailable)`; the screen shows the reason and hands the passenger the text box. Server-side VAD ends the question — no `audioEnd` control frame is sent.
- Android has no on-device speech-to-text: `AudioSpeechEngine.startListening` on Android is an honest fallback path only (permission flow + "please type your question"); the live audio path bypasses it. If the transport cannot take the audio, the real reason is shown/spoken verbatim — never invent a transcript (BUS-P0-06).
- Display-only passenger transcript: `inputTranscription` renders as `Icons.record_voice_over` + quoted text and is **never re-submitted** as a text turn. `AudioSpeechEngine.liveMicrophoneErrors` surfaces `AudioRecord` failures so "Listening…" is never left unfulfillable. Emoji never stand in for icons.
- Continuous hands-free listening: once enabled it stays active across turns — web auto-restarts on silence/timeout; Android keeps the stream open, withholding frames while the assistant speaks (`AndroidVoiceTurn.pause`/`resume`, auto-resume ~350 ms after speech) so the passenger can interrupt and the reply is not re-heard as a question.

**Booking personalization — opt-in and allowlisted:**
- `AppSettingsController` carries `preferredPassengerName` / `defaultPassengerType` / `useBookingPersonalization` (off by default; all hydrate-validated).
- Gemini may pull context only through the read-only `get_booking_context` tool (silent protocol, no arguments, at most once per booking attempt) — never from the general system instruction.
- `BookingContextBuilder.build` emits exactly: profile (name/default type, only when opted in), communication presentation settings, resolved saved-place names, ≤3 non-demo trip summaries, and the current draft. Demo tickets, ticket IDs, QR payloads, fares, timestamps, contacts, locations, and API keys never serialize; draft slots reduce to `{value, source}` pairs.
- Slot provenance (`BookingValueSource`) decides readiness: only `passenger` and `profileDefault` sources satisfy — the `18B`/`UPI`/`general` constructor fallbacks and staged recent-trip suggestions (`stageRecentTripSuggestion` → `acceptStagedSuggestion`) can never masquerade as choices. `confirm_booking` reports `success:false` with missing slots until trip + bus + passenger type + payment are all explicit. Tool dispatch returns the app's validated result through `GeminiLiveSession.onToolCall` (id/name preserved; callback failures and unknown tools get bounded failure envelopes).
- Pinned in `booking_context_test`, `app_automation_controller_test`, `tool_command_safety_test`, `gemini_live_transport_frames_test`, and the `gemini_live_test` integration group.

**UI, accessibility & lifecycle contracts:**
- **Home-root shell (2026-10-18)**: `AppNavigationShell` (`lib/features/navigation/app_navigation_shell.dart`) uses one nested `Navigator` with Home as its root and no bottom navigation bar. Home's route, booking, and ticket actions open their pages on that stack; its More button opens `MorePage`, which owns Safety & Contacts / Corridor Alerts / Settings. System Back pops the current page and exits only from Home. Emergency SOS stays the red Home card (`idSafety`) and the More safety entry.
- **Accessibility floor**: all interactive controls meet 48×48 dp (WCAG 2.2). Platform `TextScaler` is preserved without artificial clamping (Astra P0) — reflow at large scales, never clamp. Fixed-height containers that could clip at 300 % use `minHeight` + reflow. Red of any kind is reserved for Emergency SOS surfaces (`#E11D48`); home cards are neutral with a single `#007AFF` accent bar; the sticky "Ask BusBuddy" bar is `colors.actionPrimary` on every page. Home/search navigation has a 500 ms double-tap guard. Checkout fare/pay stacks below 360 dp and wraps above.
- **Home & saved places**: saved places own no home option and no page — they are one-tap `SavedPlaceChips` inside the booking origin/destination pickers and the Find-a-Place stop picker (tap selects, star toggles, persisted as stop IDs in `AppSettingsController.savedPlaceStopIds`). Ticket history lives only in My Tickets.
- **Live GPS screens** must never render invented telemetry: no data → "Waiting for live GPS…" with an indeterminate indicator; stream errors → honest error card with Retry. Show an `Updated HH:MM:SS` timestamp from telemetry as plain text (never a live region — the stream ticks too often); manual refresh announces politely through `AnnouncementCoordinator`; telemetry announcements fire only on next-stop *change*, never per tick. Destination arrival is a one-shot post-frame `_onArrival`: expire via `completeActiveTrip` only if the ticket is still active, announce politely, show the non-dismissible `Destination Reached` dialog with its 10-second countdown, then `popUntil(isFirst)`; the timer is dialog-local and cancelled in dispose.
- **Design tokens (Chunk 50)**: build UI from `AppTheme.colors(context)` / `AppSemanticColors` / `AppSpacing` only — never hardcoded hex (raw `Colors.white` as text counts as a violation). Radii are 8/14/20/pill (`AppSpacing.radiusSm/Md/Lg/Pill`). `FareQuote.formattedAmount`/`formattedBaseFare`/`formattedSavings` format exact-from-paise (no `toStringAsFixed` on doubles anywhere); settings hub trailing captions must read real `AppSettingsController` values, not static strings.
- **Teardown must never strand process-wide state (Chunk 49)**: `AiControlGlow.instance`, the model-audio `AudioTrack`, and the microphone feed outlive a single screen, and `State.dispose` stops at the first exception. All teardown goes through `runDisposeSteps` (`lib/core/a11y/dispose_guard.dart`), which isolates each step and **runs the process-wide resets first** (glow, then the microphone/voice-turn release). Keep new process-wide releases at the top of that list; never append one below an engine or socket call. `LiveLocationScreen`, `TicketController`, and speech sessions cancel active `StreamSubscription`s and `Timer`s in `dispose()`.
- **AI control edge glow**: `AiGlowFrame` (`lib/features/ai_assistant/ai_control_glow.dart`) paints the pulsing glow on the top/bottom bars and side rails whenever `AiControlGlow.instance.mode != idle` (blue listening / violet speaking / amber acting); it is stacked above the navigator in `MaterialApp.builder` and driven solely by the `setState` override in `GeminiLiveScreen`. Decorative by contract — `IgnorePointer` + `ExcludeSemantics`, no audio, no live region; the pulse only runs while active so `pumpAndSettle` still settles. Never add semantics, hit-testing, or a second animation owner.
- **Integer paise invariant**: all currency is integer paise (`1 INR = 100 paise`) in `FareEngine`/`FareQuote`; zero floating-point arithmetic in financial logic.
- **Composition root**: `AppServiceLocator` (`lib/core/di/service_locator.dart`) is the sole DI root; subscriptions and resources implement `AsyncDisposable`.
- **Lexical scope**: pure-Dart entities live in `lib/domain/`; `lib/data/models/transport_models.dart` imports and exports `Stop`.

**Architecture Decision Records** (`docs/adr/`): ADR-001 (domain & a11y contracts), ADR-002 (accessibility & safety architecture), ADR-003 (production readiness & audit resolution), ADR-004 (Android native voice I/O & spoken-question audio-in).

**Environment notes**: OpenStreetMap tiles + OSRM routing require network (tests log 400s for tile requests). Web speech features use conditional imports (`dart:html`, `dart:js`, `dart:js_util`) that compile only on the web target. `flutter run -d chrome` can fail to attach ("Failed to launch browser after 3 tries") when the machine is loaded (e.g. a Gradle build running) — the proven fallback is `flutter run -d web-server --web-port=8080`, then open `http://localhost:8080` in Chrome (hard-refresh Ctrl+Shift+R after a rebuild; press `R` in the run terminal to rebuild).

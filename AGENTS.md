# Repository Guidelines

This guide records repository-specific practices and agent workflow.


All BusBuddy source code, tests, documentation, progress files, and generated project artifacts must be stored under `/home/pavan/BusBuddy`. External folders may be read as reference inputs only; temporary extraction directories are not deliverable locations.

## Project Structure
This repository contains a Flutter/Dart-based accessible public transport assistant prototype called BusBuddy, focused on a Vellore, India demonstration. The codebase is organized around journey modeling, route search, accessible UI, and realtime bus tracking. A Python script (`create_research_doc.py`) generates the associated Word document using the `python-docx` library. Source code (.dart files) is present under `lib/` with feature-based organization (`features/`, `core/`, `data/`).

## Testing Guidelines
- Flutter widget tests using `WidgetTester`, `SemanticsHandle`, `pumpAndSettle`, `pump` for timers.
- Guidelines for tap-target, label, contrast, and semantics from research document.
- Manual Android testing with TalkBack and Accessibility Scanner recommended.
- Task testing with at least one relevant blind/low-vision participant advised; relying on blindfolded sighted participants alone is not sufficient.
- Usability measures: completion rate, time, errors, number of recovery actions, confidence, SUS score.
- Test files live under `test/` mirroring `lib/features/` and `lib/data/` structure.
- Native Android voice work is covered headlessly where possible: `test/features/ai_assistant/android_voice_turn_test.dart` drives the spoken-turn state machine through injected streams, and `native_audio_channel_test.dart` asserts the bridge degrades honestly when the platform channels are absent. An emulator is also not enough: a run on an API 34 AVD (2026-09-30) proved the build, install, permission contract and honest-failure paths, but the AVD has no working TTS engine, no hardware AEC and no TalkBack, and without a valid Gemini API key `_awaitLiveReady` never opens the microphone — so the permission dialog and the audio-in round trip are unreachable there too. Those still require a physical device with a valid key (`flutter run -d android`, `adb logcat -s BusBuddyVoiceChannel:V`) — do not claim them verified from a green test run, and do not claim them verified from an emulator run either.

## Key Runtime Notes
- **Microphone state must be earned, never assumed**: `GeminiLiveScreen._isListening` starts `false` and is set only once capture is genuinely open. It previously defaulted to `true`, which both advertised "Continuous Mic Active"/"Listening…" with no microphone open and made `_startMicrophoneListening` early-return on its own `_isListening` guard, so the first open never started capture on *any* platform. Every mic start — every platform — now goes through the `_awaitLiveReady` gate in `_gatedMicrophoneStart`: with no API key (the common first-run case) the screen says the microphone stayed off and names the key, instead of the web regression where "Continuous Mic Active"/"Listening…" rendered under a NOT CONNECTED banner (found live in Chrome, 2026-10-11). On web the claim is earned twice over: the bridge (`__bb_start_recognition`, v10) fires a fifth `onStarted` callback from recognition `onstart` — Chrome's permission prompt sits between `start()` and `onstart` — and only that flips the flag (plus the chime); "Preparing the microphone…" holds until then. When the session reaches "Live Ready" the continuous mic auto-opens, so the key dialog flow ends with a working microphone instead of a dead promise. Three recognition cycles ending with no transcript at all (wrong input device, muted mic — `no-speech` is deliberately not an error) stop the continuous loop with "I couldn't hear anything…" instead of restarting "Listening…" forever; `audio-capture` and `service-not-allowed` name their real causes. Regressions are pinned in `test/features/ai_assistant/voice_session_lifecycle_test.dart` (*BUS-P1-08 Microphone State Honesty*). Keep failure messages naming the *real* reason — "still connecting" is wrong when no API key is set, which is the common first-run case.
- **Gemini Live voice requires a valid Google AI Studio API key** (set via in-app dialog or `--dart-define=GEMINI_API_KEY`). The key is **never written to disk** (pinned in `test/data/persistence_test.dart`: hydrate ignores it, snapshots exclude it), so an app restart needs re-entry unless the key comes from `--dart-define`. Every connect is gated on validation (`GET v1beta/models`, `GeminiLiveSession.validateApiKey`) and the screen reconnects on any key/model/voice change via a debounced settings listener — a key saved from the settings page reaches the open Live screen, which was previously impossible. Statuses name the real failure (`Key Needed` / `Validating API key…` / `Key Invalid` / `Disconnected (code …)`); socket-open no longer reports connected before `setupComplete`. Audio I/O is platform-native: Chrome web uses the Web Speech APIs; Android uses `BusBuddyVoiceChannel` (`android/app/src/main/kotlin/com/busbuddy/app/BusBuddyVoiceChannel.kt`) — `TextToSpeech` replies, 24 kHz `AudioTrack` playback built on `USAGE_ASSISTANCE_ACCESSIBILITY` (so hardware echo cancellation stays engaged while the mic is open), `ToneGenerator` chimes, plus 16 kHz mono `AudioRecord` capture streamed over the `busbuddy/voice/mic` event channel. `RECORD_AUDIO` is requested just in time (announced first, rationale-aware, "never ask again" detected via SharedPreferences).
- **Android spoken questions now reach Gemini Live (audio-in)**: `GeminiLiveSession.sendRealtimeAudio` packs microphone PCM into `realtimeInput.mediaChunks` (`audio/pcm; rate=16000`) and is gated on `GeminiLiveSession.isReady` (socket open **and** `setupComplete` received). One spoken turn is owned by `AndroidVoiceTurn` (`lib/features/ai_assistant/android_voice_turn.dart`), which forwards chunks, pauses while the assistant speaks, and reports every failure exactly once through `onTurnLost(reason, microphoneUnavailable)`; the screen then shows the reason and hands the passenger the text box. `GeminiLiveScreen` waits up to 4 s for the handshake before opening the microphone (`_awaitLiveReady`), never leaves capture open on a dead socket, and releases the turn on text turns, mic-off taps and `dispose()`. Server-side VAD ends the question, so no `audioEnd` control frame is sent. Platform detection uses `Platform.isAndroid` through `native_platform_io.dart`, never `defaultTargetPlatform` (which `flutter_test` fakes as Android). *Code-complete, unit-tested, and exercised on an API 34 emulator on 2026-09-30 — which is how the Chunk 45 microphone-state lie was found. The audio-in round trip, permission dialog, echo cancellation and TalkBack remain unverified because that run had no valid Gemini API key; see ADR-004 §3.1 for exactly what is and is not proven.*
- **Android has no on-device speech-to-text**, so `AudioSpeechEngine.startListening` on Android is an honest fallback path only (permission flow + "please type your question"). The live audio path bypasses `startListening` entirely; if the transport cannot take the audio, the reason is spoken/shown verbatim rather than a transcript being invented (BUS-P0-06).
- **Display-only passenger transcript**: `inputTranscription` text is shown as a voice-icon + quoted text (`Icons.record_voice_over` + `"…"`; formerly the `🗣️` emoji, de-emojified in Chunk 50) and is never re-submitted as a text turn — the audio it transcribes already reached the model. `AudioSpeechEngine.liveMicrophoneErrors` surfaces `AudioRecord` failures (no usable input, access revoked) so a "Listening…" promise is never left unfulfillable.
- Current Live API model: `models/gemini-3.8-live` (configured in `AppSettingsController` default).
- **Official Google Prebuilt Voices**: Supported voices are `Aoede` (default female), `Kore` (calm female), `Charon` (informative male), `Puck` (upbeat male), and `Fenrir` (deep male). Configurable in Voice Assistant Settings or via `--dart-define=GEMINI_VOICE=Aoede`.
- **Natural Voice Conversational Delivery**: The assistant executes tool calls seamlessly in the background and delivers concise, natural transit answers without verbally reading out raw JSON, function signatures, or execution mechanics.
- **Persistent Continuous Hands-Free Listening Mode**: Once the microphone is enabled, listening stays continuously active across conversational turns, auto-restarting on silence/timeout (web), auto-resuming 350 ms after the AI finishes speaking, and debouncing acoustic feedback. On Android the stream stays open across turns instead: frames are withheld while the assistant speaks (`AndroidVoiceTurn.pause`/`resume`) and flow again as soon as it stops, so the passenger can interrupt, and the pause also keeps the reply from being re-heard as a question.
- **Single-Speaker Audio Architecture, model audio restored (Chunk 43 → Chunk 49)**: Chunk 43 removed Gemini's native PCM playback entirely and made `AudioSpeechEngine.speak` the only speech producer, because Android's device `TextToSpeech` was the only voice available and double-voice bugs were unfixable around it. That worked, but the voice was robotic. Chunk 49 re-wired the model's own audio and **redesigned the contract rather than adding a second path**: there is still exactly one voice per turn, decided by `ModelVoicePlayer` (`lib/features/ai_assistant/model_voice_player.dart`).
  - **The rule**: if Gemini streamed audio for a turn (`ModelVoicePlayer.hasModelAudioThisTurn`), that audio *is* the reply and TTS is skipped entirely. TTS speaks **only** turns that carried no audio — plain text turns, the REST fallback, a socket without audio. `onTurnComplete` no longer speaks a reply that already played as audio; a reply can still be both spoken and acted on, so the tool call below must not be skipped.
  - **The end of a turn**: for model audio the turn ends on the playback drain — the native `onPlaybackDrained` notification (`AudioTrack` buffer empty + 140 ms) on Android, or the Web Audio queue-drain timer on web — not on the TTS `onAudioEnded` callback. With no TTS utterance running, that callback never fires and the microphone would stay paused forever after the first spoken reply. A 30 s `_armWatchdog()` backstop covers a lost drain.
  - **Where it applies**: Android **and** web (`ModelVoicePlayer.isSupported` is `kIsWeb || platformHasNativeAudio`). Android plays through the native `AudioTrack`; web plays the same 24 kHz PCM16 through the Web Audio context the listening chime already uses (`__bb_play_model_audio` / `__bb_stop_model_audio` in `web_speech_real.dart`, bridge v6), so the existing gesture unlock primes it and there is no second audio stack. `platformHasNativeAudio` uses `Platform.isAndroid` via `native_platform_io.dart`, never `defaultTargetPlatform`. Desktop and `flutter_test` support neither and fall back to TTS.
  - **Why web needed this**: Chrome used to drop every model-audio chunk and speak through `speechSynthesis`, which is silent on a host with no system TTS engine — a perfect text transcript with no voice at all. A chunk that will not schedule returns false, leaving `hasModelAudioThisTurn` clear so that turn still falls back to TTS.
  - **The page JS bridge is verified, never assumed** (ADR-004 §3.5): `web_speech_real.dart` installs its functions by evaluating JS into the page, and nothing but the browser ever executes that. Installation is therefore checked — calls resolve the entry point and invoke the **function reference** (`Function.prototype.call`), so a missing bridge is an observable `null` and not a `NoSuchMethodError` at the call site; every install verifies the required entry points and resets the initialized flag if any is missing, so a failed eval can never look successful through the page-written version stamp. A missing entry point is reported once, by name, naming the fix. Do not "simplify" this back into blind `js.context.callMethod('__bb_…')` calls.
  - **Still forbidden**: speaking a reply through *both* paths in one turn, and adding a second `AudioTrack`/`TtsFallbackArbiter`-style owner. `ModelVoicePlayer` is the only model-audio producer; `AudioSpeechEngine` is the only TTS producer. Barge-in (`onInterrupted`) must stop playback, not just TTS.
  - **Unverified**: model-audio playback has never been run with a live Gemini session — on hardware or in the browser. The wire path is unit-tested, the native `AudioTrack` bridge is built and tested, the web bridge JS is executed under Node against stubbed globals, but "it sounds natural" is not a claim this repo can make yet — see ADR-004 §3.1, §3.4 and §3.5.
- **Accessibility & Touch Target Standards**: All interactive controls conform to 48x48dp minimum tap target sizes (WCAG 2.2). Platform `TextScaler` is preserved without artificial clamping per Astra P0 requirements, supporting responsive reflow at large accessibility text sizes.
- **Home & Usability Contract (Chunk 47, amended)**: Home cards are neutral surfaces with a single `#007AFF` accent bar — red (`#E11D48`) is reserved for Emergency SOS, which sits 2nd in the default order. Saved places own no home option and no page: they are one-tap `SavedPlaceChips` inside the booking origin/destination pickers and the Find-a-Place stop picker (tap selects, star toggles membership, persisted as stop IDs in `AppSettingsController.savedPlaceStopIds`). Ticket history lives only in My Tickets. Home/search navigation has a 500 ms double-tap guard. Checkout fare/pay stacks below 360 dp and wraps above so 300% text scale never overflows. Live GPS screens show an `Updated HH:MM:SS` timestamp from telemetry as plain text (never a live region — the stream ticks too often); manual refresh announces politely through `AnnouncementCoordinator`.
- **Resource Lifecycle Disposals**: `LiveLocationScreen`, `TicketController`, and speech sessions cancel active `StreamSubscription` and `Timer` instances in `dispose()` to eliminate memory leaks and background CPU cycles.
- Web speech features use conditional imports (`dart:html`, `dart:js`, `dart:js_util`) — only compile on web target.
- **Single Voice Surface (floating assistant removed)**: The floating BusBuddy AI bubble and multitasking window were removed (Chunk 42, double-voice fix). Full-screen `GeminiLiveScreen` is the app's sole voice/chat assistant surface and its sole audio session owner; all "Ask BusBuddy" entry points (home cards, ticket pages, settings) push it directly via `Navigator.push`. Do not reintroduce a second audio/TTS owner without redesigning the single-speaker contract (the old `TtsFallbackArbiter` was deleted in Chunk 43 and must not be resurrected as a second voice path).
- **Teardown Must Never Strand Process-Wide State (Chunk 49)**: `AiControlGlow.instance` is a singleton painted above the navigator by `AiGlowFrame`, and the model-audio `AudioTrack` plus the microphone feed also outlive a single screen. `Flutter`'s `State.dispose` stops at the first exception, so when `GeminiLiveScreen.dispose` reset the glow *after* `_liveSession.dispose()`, a throw in that live-socket teardown skipped every step below it and left the edge glow lit over Home for the rest of the process. Widget tests never saw it because every native and socket call is faked there. All teardown now goes through `runDisposeSteps` (`lib/core/a11y/dispose_guard.dart`), which isolates each step and **runs the process-wide resets first** (glow, then the microphone/voice-turn release). Keep new process-wide releases at the top of that list; never append one below an engine or socket call.
- **AI Control Edge Glow (Chunk 48)**: `AiGlowFrame` (`lib/features/ai_assistant/ai_control_glow.dart`) paints the pulsing glow on the top/bottom bars and side rails whenever `AiControlGlow.instance.mode != idle` (blue=listening, violet=speaking, amber=acting). It is stacked above the navigator in `MaterialApp.builder`, so it follows the assistant across every screen the AI opens. Driven solely by the `setState` override in `GeminiLiveScreen`. Decorative by contract — `IgnorePointer` + `ExcludeSemantics`, no audio, no live region; the pulse only runs while active so `pumpAndSettle` still settles. Never add semantics, hit-testing, or a second animation owner to it.
- **Integer Paise Monetary Invariant**: All currency calculations are strictly represented in integer paise (`1 INR = 100 paise`) in `FareEngine` and `FareQuote`. Zero floating-point arithmetic is permitted for financial logic.
- **Design-Contract Polish (Chunk 50)**: The token system is enforced across every major screen — build UI from `AppTheme.colors(context)` / `AppSemanticColors` / `AppSpacing` only, never hardcoded hex (raw `Colors.white` as text counts as a violation). Red of any kind is reserved for Emergency SOS surfaces; the sticky "Ask BusBuddy" bar is `colors.actionPrimary` on every page. Live GPS screens must never render invented telemetry: no data → "Waiting for live GPS…" with an indeterminate indicator, stream errors → an honest error card with Retry. Destination arrival on the live map is a one-shot post-frame `_onArrival`: expire via `completeActiveTrip` only if the ticket is still active, announce politely, show the non-dismissible `Destination Reached` dialog with its 10-second countdown, then `popUntil(isFirst)`; the timer is dialog-local and cancelled in dispose. Telemetry announcements fire only on next-stop *change*, never per tick. Radii are 8/14/20/pill (`AppSpacing.radiusSm/Md/Lg/Pill`); emoji never stand in for icons; interactive controls meet the 48dp floor and fixed-height containers that could clip at 300% text scale use `minHeight` + reflow instead. `FareQuote.formattedAmount`/`formattedBaseFare`/`formattedSavings` format exact-from-paise (no `toStringAsFixed` on doubles anywhere); the settings hub's trailing captions must read real `AppSettingsController` values, not static strings. See the Chunk 50 session log in `progress.md` for the full list of reverted-if-disagreed judgment calls.
- **Composition Root**: `AppServiceLocator` (`lib/core/di/service_locator.dart`) is the sole dependency injection root. Subscriptions and resources implement `AsyncDisposable`.
- **Lexical Scope & Models**: Pure-Dart entities reside in `lib/domain/`. `lib/data/models/transport_models.dart` imports and exports `Stop` (`import '../../domain/transit/entities/stop.dart'`).
- **Architecture Decision Records**: Formal ADRs are recorded under `docs/adr/`: `ADR-001` (Domain & A11y Contracts), `ADR-002` (Accessibility & Safety Architecture), `ADR-003` (Production Readiness & Audit Resolution), `ADR-004` (Android Native Voice I/O & Spoken-Question Audio-In).
- OpenStreetMap tiles + OSRM routing require network; tests log 400s for tile requests.
- `create_research_doc.py` requires `python-docx` (executable with Python 3.12 or via virtual environment such as `/home/pavan/TrustRAG/.venv/bin/python create_research_doc.py`).

Audit basis and repository reconciliation
This audit treats the public main branch of sricharan24-byte/HELEN, retrieved on 20 September 2026, as
authoritative. Source was inspected across the available lib/, test/, android/, and docs/ paths. Direct
checkout and local execution were blocked by the workspace network proxy, so the reported test count was
not independently rerun. Every issue below is tied to code visible in the public repository; test status is
therefore “reported”, not independently verified.
The inspected branch does not match the supplied completion inventory:
• The README reports 214 tests, not 236.
• docs/adr/ADR-002-phase2-accessibility-and-safety-architecture.md is not available at the
stated public path.
• The fare engine is at lib/domain/ticketing/entities/fare_engine.dart, while production ticket
flows continue through legacy double models and hard-coded card fares.
• Semantic colors are in lib/core/tokens/app_semantic_colors.dart; the light/dark primary blue
with white text measures approximately 4.10:1, below WCAG AA for normal text, and high-contrast
error red on the high-contrast background measures approximately 5.15:1, below the claimed 7:1 AAA
target.
• The floating overlay does not contain the claimed BlockSemantics barrier or accessible corner-reposition
actions.
• Android voice capture returns a delayed hard-coded phrase and Android speech playback completes
without producing audio. The full voice implementation is web-only.
These are release-relevant source/documentation discrepancies, not naming preferences.

Section C: Master Implementation Order for the Coding Agent

The coding agent should use the following zero-regression loop. At every numbered task: create or update
the specified tests first, implement only that task, run domain/unit/widget tests plus static analysis, and
commit only after the baseline is green.
1. Freeze evidence. Record the current commit SHA, capture current test/analysis output, publish or
correct ADR-002, and make CI report its own test count (BUS-P2-03). This prevents further audit
drift.
2. Correct text scaling first. Implement BUS-P0-03 and its 320dp/300% harness. All subsequent UI
work must pass that harness.
3. Unify currency/domain flow. Implement BUS-P0-01 before modifying ticket state, because the
state machine must persist the canonical quote.
4. Build ticket ledger/state machine. Implement BUS-P0-02, including durable storage and
QR/payment feature gating. Run migration/restart/replay tests.
5. Make teardown deterministic. Implement BUS-P0-04; use the resulting cancellation and ownership
primitives for later network/audio work.

cannot duplicate emergency or financial commands.

Release decision
Decision: NO-GO for production release. The application may continue as a clearly labeled
prototype. A production release requires all seven P0 tasks and P1 tasks BUS-P1-01 through BUS-P1-10
to be complete, with independently rerun CI and device evidence. The most consequential defects are not
cosmetic: the live ticket flow bypasses the currency authority, Android voice is simulated, an AI emergency
tool can report an action that did not occur, platform text scaling is altered, and the Android release is
debug-signed.
